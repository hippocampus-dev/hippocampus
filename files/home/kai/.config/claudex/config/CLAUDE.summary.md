## Final Summary

1つの指示に対する作業を終えて次の指示待ちに入る際のレスポンス(最終まとめ)は、以下のテンプレートに厳密に従い、プレースホルダの置換以外の変更を加えてはなりません。

```
---

## 最終まとめ

以下は直前の実質的なレスポンスの再掲です。

{{逐語反復}}

### 据え置きとした指摘

{{据え置き}}

### 直前の指示とネクストアクション

{{ネクストアクション}}
```

出力するかどうかは以下で決まります。

| 状況 | 最終まとめ |
|------|-----------|
| 1つの指示に対する作業を終えて次の指示待ちに入る | 出力する |
| ネクストアクションが指示待ちで、`### Feedback` がユーザに聞く対象として定めるものがある | 出力してから、同じレスポンスで `### Feedback` が定める形の提示を行う |
| レビューが複数回に分けて到着する | すべて出揃ってから1回だけ出力する |
| 作業が終わっておらず次の指示待ちに入らない | 出力せず、何を待っているかを1行で述べるに留める |

`{{逐語反復}}` に入れる実質的なレスポンスは以下のとおりで、そこから省略・抽象化してはなりません。

| 場合 | 実質的なレスポンス |
|------|-------------------|
| 通常 | その指示に対して最後に出力したレスポンス(停止時チェックの差し戻し、リマインダ、サブエージェントの結果など、ユーザ以外から届くプロンプトへの応答や進捗連絡は含まない) |
| そうしたプロンプトを契機に内容の訂正・追加や `### Feedback` がユーザに聞く対象として定める指摘の提示が生じた | それを反映してユーザ向けに書き直した本文 |
| 実質的なレスポンスを複数出しており、最後のものに含まれない内容が先行分にある | 先行分の内容も反映してユーザ向けに書き直した本文 |

書き直した本文は単体で読んで意味が通る必要があり、差し戻しの項目番号のようなユーザに見えない文脈を指してはなりません。
`{{据え置き}}` はその時点でタスクリストに未完了で残っている据え置き項目を、その指示で登録したものか以前からのものかを問わず1行1件で入れる箇所で、記憶から書き起こしてはならず、対応・却下との区別や変更対象内か既存の欠陥かの注記も付けません。
各行は単体で読んで、対象のファイルの絶対パスと、適用しなければ何が起きるかが分かる書き方にします。
該当がなければ「なし」の1行だけを入れます。
`{{ネクストアクション}}` は直前の指示と、完了したのか、指示待ちなのか、待っているなら何を待っているのかを入れる箇所です。
`{{据え置き}}` の各行に収まらない判断材料と、選択肢を示す場合の各選択肢の判断材料は、`{{逐語反復}}` に反復される元のレスポンスに書いておきます。
