* Find the manifests using an API before dropping its entry from `FEATURE_GATE_OPTION` or from `apiserver.runtime-config` - `admissionregistration.k8s.io/v1beta1` is served only because this script names it and `cluster/manifests/mutating-admission/base/` is what depends on that, while `.github/workflows/50_kubectl-validation.yaml` carries no `paths` entry under `files/`, so the removal reaches no validation and surfaces only as that ArgoCD Application failing to sync once the cluster is next rebuilt
* A built-in admission plugin enabled through `FEATURE_GATE_OPTION` (e.g. `MutatingAdmissionPolicy=true`) runs its own informer against whichever API version of its resource this kube-apiserver build watches, independent of the `apiVersion` `cluster/manifests/mutating-admission/base/*.yaml` writes its objects at - confirm the version the plugin actually needs with `kubectl api-resources --api-group={group}` after any Kubernetes version bump in `RUNTIME_OPTION`, since a mismatch (the plugin watching `v1beta1` while `apiserver.runtime-config` enabled only `v1alpha1`, as happened moving to v1.35.1) leaves that watch's `informer-sync` permanently failing, which blocks every post-start hook behind the readiness gate and CrashLoopBackOffs `kube-apiserver` forever rather than merely leaving that one plugin unenforced
* When this script's own `sed -i`/`tee` calls against `/etc/kubernetes/manifests/*.yaml` (e.g. the `etcd.yaml` patches below) are reproduced by hand over SSH instead of by this script, never leave a second file behind in that directory (a `.bak` copy included) - kubelet's static-pod file source treats every file there as a candidate manifest and re-applies an unrelated file's content for the same pod name/namespace on its own schedule, silently reverting an edit made moments earlier; keep any backup outside the directory (e.g. `/root/`)
